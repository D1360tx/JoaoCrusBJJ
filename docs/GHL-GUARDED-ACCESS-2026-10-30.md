## API commits: decision only, not enabled

An **API commit** is an actual approved HighLevel HTTP write, not a Git commit: changing a contact field, opportunity stage, workflow configuration, publishing, sending an SMS/email, or deleting an object. Provider permission, implemented gateway tools, and human execution authorization are three separate layers. The broader raw credential could bypass the gateway if leaked: keep it server-private and do not pass it to Muse/Grok or other bots.

The actual registered tools remain `get_guarded_context`, `preview_record_patch`, `validate_saved_patch`, `save_local_message_draft`, and `read_local_message_draft`. A fresh real stdio context call returned `provider_writes_enabled: false`; no commit or approval issuer is registered. `GuardedPreparation.commit()` raises unconditionally. Preparation uses only the existing read credential. Local message drafts have no recipient and are not sent or stored in HighLevel.

If separately authorized later, first build and review a narrow owner-approval gate: GET the exact target, show the proposed diff and downstream effects/recipients, preserve before-state and rollback limits, bind independently authenticated owner approval to the exact plan SHA with one-use expiry, re-read and reject stale state, execute only that small allowlisted operation, then read back the exact target and retain an audit result. A plan signature or LLM-supplied approval string is not independent owner approval. Never blindly retry a send or destructive request after an ambiguous response.

Start with separately reviewed low-risk non-DND/non-consent record changes or isolated template Draft edits, not blanket permanent execution approval. Publication can activate all eligible contacts, potentially including backlog or existing contacts depending on triggers/settings; require impact review beyond the button. Sending is permanent external transmission, not a draft, and needs recipient/channel/content, valid consent, unchanged opt-out/DND, sender/A2P readiness, timing and estimated segment/cost checks. Deletion may be irreversible; disclose backup/recovery limits and require exact-object confirmation. Bulk actions need extra explicit approval. None of those implementations or business actions is approved or enabled by this permission expansion. Website tracking, SMS release and consent/DND policy are untouched.
